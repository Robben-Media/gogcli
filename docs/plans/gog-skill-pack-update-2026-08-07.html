Skill pack + self-update for gog CLI

CLI-scoped companion skills update with the binary. Agents get a notice, can run update, skip dirty skills, and report skips to the user.

Date: 2026-08-07 Branch: feat/skill-pack-update Repo: Robben-Media/gogcli Spec for Codex /code-review

1. Goal

When gog ships a release, machines that already use gog should be able to:

  1. Learn that a newer binary exists (notice on use / explicit check).
  2. Upgrade the binary with one command.
  3. Refresh only the Google/gog companion skills that ship with this CLI — never unrelated agent skills.
  4. Find those skills wherever they already live (.agents, .claude, etc.).
  5. If a skill was locally edited: skip by default (agent-safe); allow force overwrite for intentional human runs; always report skips so an agent can tell the user.

3. Discovery

For each manifest skill name, search known agent skill roots under the user home (and optional project cwd):

  • ~/.agents/skills/<name>
  • ~/.claude/skills/<name>
  • ~/.codex/skills/<name>
  • ~/.cursor/skills/<name>
  • ~/.grok/skills/<name>
  • ~/.factory/skills/<name>
  • ~/.config/agents/skills/<name>
  • Project: <cwd>/.agents/skills/<name>, <cwd>/.claude/skills/<name> when present

Resolve symlinks to real paths and dedupe (Jeremy’s setup: .claude/skills/* → .agents/skills/*). Update the real directory once.

If a skill is not installed anywhere: leave it alone (no mass install unless gog skills install).

4. Dirty / outdated detection

State file: ~/.config/gogcli/skill-pack-state.json records last content hash written per real path.

ConditionStatusDefault action
No install pathnot_installedSkip (unless install)
Disk hash == pack hashcurrentNo-op
Disk hash == last-written hash ≠ packoutdatedUpdate
Disk hash ≠ pack and ≠ last-written (or no state)dirtySkip unless --force
Agent policy: never force-overwrite dirty skills. Print skip lines so the agent can tell the user.
Human policy: pass --force / --force-skills when pack should win.

6. Binary self-update

  • Source: GitHub Releases for Robben-Media/gogcli (override with GOG_UPDATE_REPO).
  • Use existing GoReleaser asset naming: gogcli_<version>_<os>_<arch>.tar.gz (+ windows zip).
  • Verify against checksums.txt when present.
  • Atomic replace of the running binary path (os.Executable()).
  • Refuse auto-replace for obvious local-dev builds if version is empty/dev unless --force.

7. Check-on-use (LLM notification)

  • At most once per 24h (state: ~/.config/gogcli/update-check.json).
  • Non-fatal; network errors silent.
  • Disable: GOG_SKIP_UPDATE_CHECK=1 or --no-input paths that must stay quiet can still show check only on successful version compare (prefer always stderr only).
  • Does not auto-upgrade; only prints the notice. Agent/skill text: if notice appears, run gog update then retry.

11. Acceptance criteria

  • gog skills status lists all 10 pack skills and finds existing installs under ~/.agents / ~/.claude.
  • Editing a managed SKILL.md causes skip without --force; message names path.
  • Clean outdated skill is rewritten; learnings/ untouched.
  • gog update --skills-only never touches non-pack skill dirs.
  • Binary check returns structured “update available” line without upgrading when not asked.
  • Codex code-review completed against this plan; merge only after review disposition.
